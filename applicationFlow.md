Detailed user journey
1. Sign in: authenticate the user and resolve their permissions.
2. Open dashboard: show current incident counts, critical items, data freshness, and recent updates.
3. Find an incident: search by incident ID, keyword, category, date range, or geographic area.
4. Open the investigation workspace: load the incident summary, evidence, related events, timeline, and assessment history.
5. Evaluate evidence: inspect source, occurrence time, ingestion time, quality flags, and contradictory information.
6. Review hypotheses: compare potential explanations without presenting correlation as confirmed causation.
7. Take an action: update status, assign ownership, annotate, confirm or reject a proposed relationship, or defer the decision.
8. Record the change: the backend verifies permissions and persists the change with an audit entry.
9. Refresh the view: the UI receives the updated state and identifies what changed.

3.3 Important failure paths
Situation	Expected system behavior
Source API is unavailable	Mark source as stale or unavailable; retry safely
Duplicate event arrives	Avoid creating a second observation; preserve relevant delivery metadata
Event arrives late	Update the appropriate historical timeline and reassess if necessary
Location is missing	Retain the observation with a missing-location quality flag; do not invent coordinates
Sources disagree	Preserve both observations and mark the conflict
Fusion confidence is insufficient	Defer association instead of forcing a merge
ML service is unavailable	Use an explicitly defined safe fallback or mark assessment unavailable
LLM times out	Continue without generated prose; retain deterministic evidence and assessment
User lacks permission	Reject the backend operation and return an appropriate authorization error
Database write fails	Do not report success to the UI; retry or surface a recoverable failure
3.4 Core user-interface states
Every data-backed page should support these states:
- Loading.
- Successful data display.
- Empty results.
- Partial data or stale source.
- Recoverable error with retry.
- Permission denied.
- Offline or disconnected.
- Incomplete evidence or unavailable hypothesis assessment.
These states are requirements, not optional polish.
